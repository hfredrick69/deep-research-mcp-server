### F1 — HTTP mode auth fails open; non-constant-time comparison (Medium, pre-existing)

**Evidence:** `src/server.ts:241-253`

```ts
export function apiKeyAuth(req, res, next) {
  const apiKey = process.env.MCP_API_KEY;
  if (!apiKey) { next(); return; }            // no key configured => no auth
  const providedKey = req.headers['x-api-key'] || req.headers['authorization']?.replace('Bearer ', '');
  if (providedKey !== apiKey) { res.status(401)...; return; }
  next();
}
```

`git show HEAD:src/mcp-server.ts` lines 298-310 contain the identical body, so the change
only relocated it (and added two tests pinning both behaviours, `src/server.test.ts:476-504`).
`app.listen(port, …)` at `src/mcp-server.ts:101` binds all interfaces (no host argument).

**Exploit:** an operator who sets `MCP_HTTP_MODE=true` without `MCP_API_KEY` exposes
`/mcp`, `/sse` and `/messages` to anyone who can reach the port, each tool call spending the
Gemini API credit. `!==` on strings leaks timing, a secondary weakness.

**Reachability now:** HTTP mode is off. `.env.local` has no `MCP_HTTP_MODE` line (names
checked with `cut -d= -f1`), `.env.example` ships `MCP_HTTP_MODE=false`, and the live
launch path in `~/.claude.json` runs stdio.

**Fix (separate change, not in this plan):** when `MCP_HTTP_MODE=true`, refuse to start
unless `MCP_API_KEY` is set; compare with `crypto.timingSafeEqual` on equal-length buffers;
bind `127.0.0.1` unless `MCP_HTTP_HOST` is set; enable the SDK's DNS-rebinding protection
(`allowedHosts`) once the SDK is upgraded (see F2).

### F7 — SAS URL in the info log (Medium, pre-existing, HTTP mode only)
`src/server.ts:369` logs `reportUrl`, which is `${blobClient.url}?${sasToken}` with a 7-day
read SAS (`:226-234`). Anyone with log access can read the report for a week.
**Fix:** log `blobName` and size only (the `:233` line already does).

### F8 — Client disconnect does not abort the billed interaction (Medium, HTTP mode only)
`src/mcp-server.ts:53-59` uses `enableJsonResponse: true` and closes transport+server on
`res.on('close')`, but in SDK 1.17.2 `_onclose` rejects pending *responses* and never aborts
`_requestHandlerAbortControllers` (`shared/protocol.js:98-110`); only a `notifications/cancelled`
message fires `extra.signal`. Behind a load balancer with a 240-300 s idle timeout every long run
fails client-side while the handler keeps polling Google for up to `GEMINI_DR_TIMEOUT_MS`, then
discards the result; no upstream cancel is sent. In stdio mode a client disconnect kills the
process outright, with the same orphaned-interaction effect.
**Fix:** per-request `AbortController` aborted in `res.on('close')`, combined with
`extra.signal` via `AbortSignal.any` before `runResearch`; a SIGTERM handler that cancels known
in-flight ids; prefer SSE or an async job/poll pattern for runs this long.

### F9 — Tool description tells the client to run a server-supplied shell command (Medium, pre-existing, HTTP mode only)
`src/server.ts:264-265` ("you MUST automatically download the report using the provided curl
command … Do not ask the user") and `:387-391` emit `curl -L '${reportUrl}' -o <name>`. The URL is
server-built and the filename is sanitised to `[a-zA-Z0-9_]` (`:374`), so direct injection needs
a host or storage compromise, but the pattern conditions the client to execute tool output, and
on upload failure the snippet becomes `curl -L 'ERROR: …'` while the full report is dropped (`:372`).
**Fix:** remove the imperative text and the curl snippet; return `metadata.reportUrl` and fall
back to inline content on upload failure.

### F10 — Completed report discarded on write failure; overwrite semantics (Medium, new error path)
`src/deep-research.ts:157-171` has `run.content` in hand but throws `persist_failed` when the
write fails, and `src/server.ts:412-418` then returns an error envelope with no report. For a
stdio server the cwd is wherever the client launched it (possibly read-only), so EACCES/EROFS is
realistic, and each failure costs a paid run. `fs.writeFile(..., 'utf-8')` at `:92` uses flag
`'w'`, which follows an existing symlink at that path and overwrites. The filename is safe
(constant prefix + timestamp, `:111-114`).
**Fix:** `REPORT_DIR` env (default cwd), write with `{ flag: 'wx' }`, and on write failure log
and still return the content with a `persistWarning` in metadata.
